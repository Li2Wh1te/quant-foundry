# S2-D06｜更新状态与问题解释面板

**版本：v1.0｜第二阶段第一批｜建议角色：前端／UI**  
**依赖：S2-D01、S2-D02**  
**本包唯一交付结果：用户看得懂本次更新结果与当前数据问题，并知道可采取的只读下一步。**

基于编包时main `4c9e8167d49ef1d6bbc49afc6578208d7a339f97` 的实际页面与接口，执行时从最新main接续。先读本文件，再看COMMON/API_NOTES/INTEGRATION中与本包相关部分。不需要拿到整个旧启动包。

## 目标与范围

只做数据集详情“更新与问题”面板，不建设运维控制台。展示已有状态，不启动更新、retry、finish、清理或补采。

## 实施

1. 当前可用状态与最近更新结果分区显示。优先用descriptor.last_update；需要/status时按dataset关联，保留非业务入口计数边界。未知或未提供的refresh细节不推导为running/backoff。
2. 只展示真实存在的最近处理结果、时间、已声明计数与原因。没有可靠总量不画百分比；只返回complete不绘制五阶段全部成功。需要流程解释时提供静态简图或文字，明确不是运行轨迹。
3. 问题列表使用服务端分页，每页20项；本包可读整个分页序列但不自动拉全量。按后端能力筛dataset；未提供原因分组接口时不要把当页分组显示成全域统计。
4. 显示“问题记录数”和“受影响成员数”时采用不同标签；集合成员可能重叠，不能计算错误率。旧限制、当前限制的kind保留解释，不把所有原因都归结为供应商数据错误。
5. 已知原因用简短中文与实际下一步解释：确认依据不足、刷新失败、报告不完整、范围未处理等。SOURCE_REFRESH_FAILED不自动宣告旧数据失效；FULL_RANGE_UNPROVEN不说全部数值错误。诊断码和scope放展开区。
6. 可提供的动作仅限刷新状态、调整当前查询、查看已有数据源/采集任务页。链接只导航不执行动作，不预填秘密或建议用户盲目增加预算/删除问题。
7. 问题请求失败显示“问题读取失败”，不展示零问题或“无问题”；问题列表错误不清空已经读取的数据集说明。刷新时重置必要分页上下文，避免重复请求与重复追加；不能按显示文案去重真实问题记录。

## 验收

| 场景 | 必须结果 |
|---|---|
| 当前可读、最近更新失败 | 两个事实并列，不自动禁用所有旧数据 |
| 操作complete但覆盖/质量未确认 | 不显示全域可用或R01完成 |
| 20项当前页但全域更多 | 总数、当页、成员数清楚分开；没有假全域原因分布 |
| API失败和合法空问题集 | 两种状态不同，失败不显示“0问题” |
| 未知原因码 | 安全通用文案，技术码可定位，不吞信息不造解释 |
| 点击任何面板动作 | 仅GET或导航，不触发更新、retry、finish、清理 |

## 交付

独立面板、问题分页与状态交互测试、典型状态截图。本包不承接R01的质量修复；反馈共性展示缺口由D01统一对齐接口。
