# 共同边界：第二阶段第一批

本批目标是把已有当前数据目录变成清楚、可操作的数据工作区。复用现有 React 页面、CurrentStore 接口与已确认视觉方案，不重新建设底座，不重做全部前端。

## 本批与 R01 的关系

用户本轮已同意第二阶段与 R01 并行；这一新决定替代旧文件中“前端开发必须等待 R01 全部结束”的排期，其他正确性与保护要求继续有效。

R01 负责来源处理、当前值正确性、覆盖与质量判断、领域读取门禁、持续更新和全量验收。本批负责页面、只读请求封装、状态解释及交互。后端拒绝是事实，前端不能改 `ready/qualified/pending`，不能直接查询底表，也不能改用旧来源或候选填充页面。

基线中查询仍受全局门禁约束。R01 后续交付按领域／请求的读取判断后，本批只接入实际响应，不另写一套质量／覆盖算法。不自行设定新的后端权限字段，不用前端测试夹具证明生产已开放。

## 实施方式

- 每包一个明确结果，通常一个主 PR；不承诺固定工时，不为了凑文件数量拆任务。
- 在执行时最新 main 上接续，保留前序已合入改动。若 R01 修改共享接口，只对齐受影响的类型与响应一次，不开一轮范围审批。
- 默认只在本地或隔离开发环境运行。没有生产部署、重建、清理、数据源调用、任务启停或密钥修改授权。R01 的进行中工作不被本批中断。
- 正常回传一份短结果说明：实现内容、实际测试、界面预览、剩余接口依赖。不要新建部署版本台账、原件策略表、逐条质量签认或整套审计平台。

## 必须保留的产品边界

正式内容只有当前一套；不做历史发布、快照切换、版本回滚、逐条成功台账、流程编辑器或在线清洗规则编辑。

“来源停用”不等于本地历史不可读；“本次更新失败”不等于所有当前值错误；“处理完成”不等于数据合格或完整覆盖。以服务端对应事实展示，未知显示未知，不猜测。

`row_count` 是当前物理存储行，不自动当作行情点、证券数或业务对象数。`updated_at` 不是业务数据截至日；`partition_range` 不是完整业务日期覆盖。没有可靠分母就不显示进度百分比。

`generation` 仅用于当前读取一致性及诊断，不做历史版本功能。`DATA_CHANGED` 后旧游标与旧结果不可拼接。大整数、Decimal 字符串、纳秒时间保留精度；缺失不填 0。

## 默认 UI

用户默认看到名称、用途、频率／已声明口径、可用状态、最近更新结果以及查看入口。内部标识、存储分区、schema、规则和原因码放入按需展开的技术信息。

样式限于数据资产路由；既有总览、数据源、采集任务、A 股市场、策略与回测页面不进行全局改版。保留现有侧栏与快捷导航。新视觉取舍在本包提供可交互预览和截图验收，不另设纯设计前置包。

默认只读。按钮“刷新页面”仅重新 GET 状态，不触发采集、更新或重建。没有后端真实阶段信息时不动画模拟五步流水线；可提供“本地来源 → 标准化与校验 → 当前数据”的说明，但不得画成执行实况。

## 完成状态

开发和隔离测试通过，可以提交开发验收。真实联调尚被 R01 接口或数据条件挡住时，写清具体依赖；不把它包装成已上线，也不让这个等待迫使所有独立前端工作停工。

本批全部完成也不等于第二阶段全部完成。后续市场列表／K 线业务接入、其他页面统一以及第三阶段回测重构，不自动加入本批。
