## 实际实现与拒绝边界

**读取准入使用既有正式证明。** 原 `require_ready` 及 R01 全局完成/审计的质量检查保持默认行为。S2 `/query` 使用请求依赖准入：全局已 ready 时保留原入口；只有已完成 reset 的 `reset_done` 可按当前 entry 的完整输入证明独立读取。复用 `coverage.check_coverage` 的 sealed scan、boundary、range digest、契约、代次、待处理操作、捕获范围队列及文件契约判断，再由现有 reader 判断该对象范围的质量。

缺失证明、只有成功标志、待处理输入、代次/契约不一致，以及 rebuilding/resetting/未知维护阶段均拒绝。输出文件存在不能替代输入证明。健康 A 不再依赖无关 B 的质量结果；同 entry 内明确位于其他对象的质量限制可隔离，opaque/范围外未定位限制仍保守处理。无定位或格式未知的溢出限制不能被默认放行。全局或本 dataset 的 legacy restriction 仍拒绝；认证依赖、单 token 401 及 `allow_partial=false` 默认不变。

读取持有维护表只读保护，在返回前短暂锁定控制表并重新检查准入、限制、代次和对象质量。获取锁超过 500ms 安全拒绝，不写 ready、不改变生产状态。空的已注册对象范围仍经过 reader 质量检查。`request_satisfied` 与 `business_date_coverage_verified` 保持 false，干净数据页不宣称任意业务日期连续覆盖。

保守限制仍存在：reset_done 下需要该 entry 的当前完整输入证明；并不因部分输出存在而批准尚无证明的对象。S3 运行入口仍使用它原有的全局 gate，没有从 S2 绕行。

**目录可显式分批继续。** 每次操作仍最多 10 页 / 1000 项、每个 HTTP 页最多 100 项。预算停止后显示“继续加载目录”，只在用户点击时从下一 offset 读取；重复点击不会启动第二次读取。筛选及 URL 上下文保留，未完整加载时全局统计仍为待加载，刷新从当前目录第一页重新读取。

**当前清单一致性不提供历史读取。** `/datasets` 和 `/issues` 返回 64 位小写十六进制 `revision`，续页携带同一标识。它按当前控制行的主键及 PostgreSQL xmin、过滤条件和目录声明契约计算；不包含业务行、路径、凭据，不持久化快照或新增表。目录的 descriptor、修订标识和分页共用一个 REPEATABLE READ SQL 视图；`describe_capability` 仅增加可选共享连接，既有调用默认方式保留。

问题完整排序为更新时间、dataset、scope、kind 和内部唯一记录键；内部键不暴露给前端。修订标识可发现计数与时间戳均不变的更新，也绑定 dataset 筛选及全局限制。同版本才可前后翻页，变更返回 `409 DATA_CHANGED`，前端清除旧结果/页栈，等待用户显式重新读取。新旧目录不会拼接。首次多页响应缺少标识时拒绝，旧单页响应仍可展示。

控制清单计算有固定预算：100000 条、16MiB、5 秒，单个声明契约最多 256KiB；超预算或 SQL/锁错误明确拒绝。标识只验证当前版本，不能索取旧版本。旧直接 API 调用可不带标识读取一个新页；S2 的所有续页均带标识。
