# AR-03 原生行情增量与有界重建

## 实现与实际范围

- 默认 CLI `update`、`retry` 和 `data_store.update_local` 调度器共用范围消费者。真实增量入口为同花顺 E50–E52（stock/ETF/index daily）和 Tushare E69/E70（复权因子/ETF daily）。其他目录、日历、资料和报告仍使用原有完整本地扫描；完整报告原子性不变。显式救回文件或指定分区仍按原有完整扫描/维护语义处理。
- 复用同花顺原生观察、来源范围、revision、差异链和实际返回键。仅看最新 head/revision 无法发现中间唯一历史键、直接 DML 与晚提交，故新增可合并的当前待处理范围；不复制正文、不建立逐行成功表或永久事件台账。
- 四张原生表上的事务触发器覆盖采集 `publish/fail`、dump `publish_batch`、ETF 仓储、普通 INSERT/UPDATE/DELETE/COPY。触发器为 ALWAYS，TRUNCATE 明确拒绝。禁用捕获时消费者拒绝声称完成。绕过/删除触发器、恢复旧数据库等管理行为不属于自动发现承诺；恢复捕获后用现有 `rebuild --entry E..` 显式对账，包含 current 中仍有、原生表中已整月删除的范围。
- 同花顺每次还原一个原生观察及必要依赖，按既有顺序与冲突规则消费所有待处理观察；有完整返回键证明时不额外读取无关的前一 full anchor。请求凭据每个观察解析一次，返回键在临时内存索引中查找，不改变证据 JSON。稀疏缺项和归档差异的 removed 不构成业务撤回。
- Tushare 按标的/月读取权威完整范围，每批最多 64 个范围；批次中无效月份不授权删除，也不会阻止其他独立有效月份对账。现有来源 PK 和新增观察顺序索引定位读取，不用业务日期或 max(id) 充当完成水位。
- 队列分别保存已领取边界与后续 pending 变化。正式提交后才确认当前边界；r+1、回滚、晚提交不会因 r 已确认而丢失。跨进程保留小游标和有界工作文件，完成后释放。范围按等待时间公平推进；初始化边界完成与后续新待办分开，不要求来源永远静止。
- 保留 AR-01 的入口锁、退避、手动重试、故障隔离及写者预留。保留 AR-02 完整覆盖依据；局部范围不伪装全量，readiness/audit/finish 同时核对原生待办。正常 v2 文件、精度、价格口径及复权锚点限制不变。

## 验收证据

`backend/tests/test_data_store_incremental.py` 覆盖 I01–I12 的实际原生路径：五入口零变化、历史迟到/纠错/因子、范围删除与稀疏/空/失败、两个真实数据库事务的晚提交与回滚、消费期间新变化、提交前后退出、容量失败续作、持续写入下初始化完成、必要依赖损坏、中间历史键、入口隔离、小表删除、默认调度/CLI、实际 dump 发布、直接 DML、显式对账、迁移回滚和模型一致性。

最终代码的相关回归：653 passed、15 subtests passed（113.64 秒），包括源采集/导入、AR-01/02/03、当前存储、审计、迁移和调度。CI 尚待完成。唯一已知既有 warning 为 `TestTaskParameters` 构造函数导致的 pytest 收集提示。

增长脚本：`backend/scripts/ar03_growth.py`；最终自动报告：`ops/lf01/ar03-growth.json`。使用独立 PostgreSQL 16、受支持 Linux 数据卷、同一固定源码快照和相同预算，分别装载每条来源路径 10 万/100 万冷业务行。消费者无手工 Range 或 partition，每次 update 在新进程中运行默认分派器。G01/G05 各 100 轮；G02/G03 使用相同小新增、历史纠错、迟到与删除范围。G04 初始领域超过单工作文件预算，在多个原生范围和进程之间推进。

报告区分来源元数据范围行、原生 payload 记录/字节、必要依赖记录/字节、实际业务 JSON 解码次数/行数、规范化数、提交分区、current 读写字节、目录/当前行数、待办/控制状态、暂存采样峰值、RSS 和耗时。传输字节不是数据库物理 IO；EXPLAIN ANALYZE/BUFFERS 单独提供发现和关键源读取证据。首次迁移/显式对账枚举范围元数据，与存量身份数相关；普通 update 不重复这次枚举。同一不可拆原生观察及依赖的验证成本单列，不宣称任意尺寸观察都能无预算限制处理。

## 升级与边界

新增非破坏性 Alembic 迁移 `20261008_01`，建立范围表、索引、触发器及初始范围元数据。正常自托管 `deploy-backend` 已执行 `alembic upgrade head`；独立升级可用现有 `make selfhost-migrate`。不需要另外运行初始化脚本，不新增环境变量，不改变正式 schema，也不需要 reset 或重写已正确发布的 current。

R01 执行者在安全检查点更新程序并确认一次实际运行已使用新逻辑；数据库迁移和相关写者交接仍按现有部署流程执行。迁移对原生表的锁获取有 5 秒上限，失败整体回滚。大行情物理来源或必要依赖超出既定校验预算时，状态保留具体 active 范围/观察与失败原因，不作为空输入或完成；已提交独立范围不回退。

本包未连接生产、部署、请求供应商、重新启用 Tushare、清退或 finish。合成增长结果不代表生产分钟/Tick 已接入。最终增长验证尚在运行，完成前不标记本包交付完成。
