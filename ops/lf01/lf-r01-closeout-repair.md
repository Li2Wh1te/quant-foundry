# R01 有界收尾路径

本修复不执行 reset，不改变 v2 契约，不删除问题以满足门控，也不自动重新全库重建。

- 旧 sealed 工作沿原模式和选择续接；AR-02 可从仍存在的完整分区清单及已提交 checkpoint 核验旧断点。旧完成布尔值不能替代缺失的完整覆盖依据。
- E23/E44 使用 AR-03 原生范围队列；新增非破坏性迁移 `20261009_01` 扩展原有采集触发器允许的领域并只初始化新增领域的范围元数据，不复制原件。最多 64 个完整观察共用有限工作文件；已领取范围、观察边界、源码选择及续作身份保持稳定，提交后才推进各范围游标。
- E50/E51 沿现有 AR-03 路径，不再尝试把全部原生历史装入一次完整扫描。E52 的既有 sealed 工作应先续完，不能覆盖其输入边界。
- SQLite 进度回调引发的超时、取消和内存保护保留原错误码；只有真实 SQLITE_FULL 映射到暂存超限。其他 SQLite 失败保持 FILE_INVALID，不能冒充容量不足。
- 问题的 SQL 写入每批 256 条，但所有批次仍与 current 文件、来源 checkpoint 和 generation 同事务提交。一份原子问题变更最多 65,536 条、编码合计最多 16 MiB，另外继续执行共享问题总数上限。后续批次失败时全部回滚；解除问题仍须匹配当前 evidence token。
- 保留真实来源确认缺口、失败采集、缺失报告键、报告目录/请求不完整、不可比较来源顺序等限制。没有凭据不从请求范围或当前输出反推确认，也不调用供应商填补。

验证包括真实 PostgreSQL/Linux 文件系统上的 SQLite 原因保留、大问题事务回滚、错误 token 不解除限制、基金范围跨调用不重复读取已完成原件、sealed 基金批次恢复、迁移版本门禁，以及 AR-01/02/03、当前内核、领域适配和完整覆盖回归。生产执行结果与源数据统计仅保存于私有运维证据，不提交到公共仓库。
