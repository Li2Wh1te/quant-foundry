# S3-D09 账户、结算与公司行动

`Account` 是单运行唯一可变资金池，实现已有 `AccountPort`。只消费 D01
Decimal/整数、D02 `RuleBook` / `ScopedFeeConfig` / `OrderFeeAccumulator` /
分红税模型及 D03 的真实会话。没有 Python 算法调用、数据库、市场数据副本、
完整账户历史快照或第二份订单/成交历史。

## D06 接入顺序

1. `Account::new(initial_cash, sessions, usage, limits)`：正 CNY 初始现金，空持仓；
   会话来自 D03 已接受日历，包含本次必要的下一结算/上市/支付会话，不能补周末日期。
2. 按当前会话 `install_terms(AccountTerms::resolve(...))`。规则/费用必须真实按日期
   解析；`SaleProceedsRule` 明示卖出现金何时可用，不能从股份 T+ 规则猜。分红扣缴
   还需要真实 `disposal_settlement_date`；自然月歧义可提供已接受的持有期事实。
   首次受理后佣金、最低收费、包含项、舍入及账户投资者配置锁定；新日法定费率
   仍使用原订单配置覆盖的实际日期，不能把账户配置修改带进同一运行。
3. D06 解析 quantity/value/target、申报阶段/权限、活动委托与合法数量；调用
   `reserve_order(ReservationRequest)` 使用 D06 唯一订单 ID、有效会话及原价估算。
   已知停牌不新增预留。账户的 `validate_and_reserve` 接受已规范化数量，零数量
   返回无动作；它不再实现一套 target/订单生命周期。
4. 账户允许预留不足覆盖整单但足够支付一个合法申报单位的买单。D06/D07/D08
   在真实候选价格下调用 `max_affordable`（受检整数商余数/费用预览），再提交
   合法可支付部分；超额成交明确拒绝。不能预支未成交卖款或其他订单冻结现金。
5. D03 调用新增的默认兼容 `AccountPort::assess_fill`，仅允许修改 `Fill.fee`，
   然后 `apply_fill`、通知及 ResultSink 写同一核定费用。D09 从自己的订单累计器
   预览并核对费用；费用不是由 SDK 或 matcher 另存一份累计状态。
   `assess_fill` 只预估，不推进金额、佣金累计或账户修订；`apply_fill` 重新核对后
   只提交一次，不能把预估结果再作为一次记账。
6. `release` 幂等，只释放余量/预留，不退回已成交份额、不多收最低佣金。
   全成交自动释放订单预留。D03 的 `settle` 推进精确会话，开放到期份额/现金，
   GTC 的余量、冻结量及累计最低佣金保留，D06 调用 `recheck_order` 检查新日事实。
7. 原子 target 替换或公司行动/订单状态批次用 `preview` → 完成 D06 订单候选 →
   `commit`；失败时两边都不提交。候选私有、账户绑定且有修订检查，不能跨资金池
   或在新的变更之后应用。`transact` 是同一机制的同步便利方法。不要在预览闭包
   中写 ResultSink/数据库或修改活的订单对象，先完成所有可能失败的工作。

常规成交只复制受影响持仓、预留及税务权益；跨会话/命令批次使用有界候选。
本实现保留当前 FIFO 税务份额及少量公司行动状态；已结束订单/成交由 ResultSink
持久化，账户不建立逐 Tick 成功账本。D06 保证订单/成交 ID 全运行唯一和有序输入，
不把直接重复调用账户方法当作消息重放协议。

## 会计与阶段

- `cash = available_cash + frozen_cash`。冻结现金包含订单预留及按明确规则暂不可用
  的已成交卖款；权益只加一次 cash，再加 receivables 和有效原价持仓市值。
- 买入净支出含费用，成本总额按 12 位 half-even 保留。部分卖出用 D01 原始有理数
  成本分摊；最后一份释放全部剩余成本。展示均价 12 位 half-even，从不反写成本。
- `AccountTotals` 是累计已实现损益、交易费、已确认分红收入及分红税；交易费用在
  `Fill.fee`，FIFO 延迟分红扣缴另列 `dividend_tax`，不伪装成多一次佣金。
- `add_corporate_action` 严格检查已公开事实、身份、必要条款、来源和阶段。
  `advance_corporate_actions` 在登记会话关闭捕获持仓，在除权会话盘前确认权益，
  支付在提供的盘前/会话关闭边界发生。D03 新增默认兼容 `session_end` 钩子，
  最后行情处理后、收盘 Bar/Tick/定时回调及 DAY 到期/after_close 前调用一次，
  停牌无行情的标的也能登记。同纳秒 close Tick 仍逐笔回调，关闭处理等末笔成交。
  D06 账户适配必须同时转发 `AccountPort::check_session_end` 到本 `Account`；
  D03 在关闭钩子后执行纯后置检查，漏登记/除权/支付即拒绝，不依赖策略主动查
  账户。方法保留源码兼容；关闭后置检查默认 `CAPABILITY_UNAVAILABLE`，漏转发
  明确失败。旧 clock-only 隔离适配显式承认自身无账户业务，不能当真实集成证明。
  终点为关闭日且已清仓也检查全部已到期权益，不能把漏支付留在应收中标完整。
  漏登记/除权/支付边界会拒绝，不事后用当前持仓推算。
- 现金分红登记不先加现金；除权确认应收，已知初始扣缴以净应收和税费表达；支付
  只把净应收移为现金。D02 的 2013/2015 税模型通过 FIFO 和真实转让交收日期
  算最终负担，累计应扣减已扣，卖出早于支付也不丢权益或重复扣税。
  延迟扣税的内部权益分摊不直接进入现金：累计调整按明示结算精度舍入，再减已
  实收调整；部分卖出不会产生分以下的现金扣款。
- 股份分配按登记权益授予，拆并作用于当时持仓；总成本保留，可卖会话单独指定，
  历史现金分红的总权益不随拆股增加。股份税费需投资者匹配、在除权边界扣缴的
  明确事实；其他扣缴时点需另有规则接入。当前
  支持逐份额可整除的比例。零碎股份缺少分配/补偿事实时 `RULE_UNAVAILABLE`。
- 除权保守取消该标的所有尚未成交的 GTC 和下一会话 DAY 余量，释放预留，报告
  `cancelled_order_ids`；D06 必须原子改订单状态并通知，不能伪造调整后的优先级。
- 配股采用不参与、不追加外部资金；比例、认购价、非交易权利和无放弃补偿均须
  明确。必要事实缺失、可交易权利或补偿未支持时拒绝。报告中的政策/公司行动
  effects 交 D11/D13 有界保存，不得忽略后宣称完整收益。

## 估值及事实边界

`mark(MarketEvent)` 消费已完成 raw Bar/TradeTick。QuoteTick 没有最后成交价，
不生成中点或把 bid/ask 当最后原价。`set_raw_mark` 只接受明确 raw 观察/有效
除权原价依据，研究复权输入拒绝；除权清除旧 mark，不用模型自动除法造新价。
`valuation` 给现有 D01 `AccountView` 及价格时间/stale/reason：盘前可以明示用
此前 raw 估算，已知当日停牌可用最后 raw；交易时段未知缺价保持 `None`，
不填零、不把未知推成停牌、不跳日拼收益。终点不强平。

这里实现的是代码与隔离业务路径。正式市场/历史公开时间/因子、公司行动及资金
可用/股份税事实的 D04 映射尚未全启用，D02 历史规则/投资者/ETF/北股等缺项
继续 `RULE_UNAVAILABLE`。D06 生命周期、生产数据联调、D10 绑定、D11 结果分析、
部署及清理不由本模块冒充完成。隔离用例不能作为生产证据。

测试入口：`cargo test -p qf-core --locked --test accounting`；独立预期直接读取
本次包提供、此前仓库缺失的 `contracts/accounting_cases.json`。时序/网关等其他
包的案例仍由所属模块处理。`tests/accounting/engine.rs` 使用真实 D03/D09 及
真实 D02 费用逻辑，host/data/matcher/订单存储明确是隔离适配。

旧 Python `accounting.py` / `dividends.py` 仍被旧 runtime、settlement、结果模型
等消费；未提前删除活的共享/执行依赖。新 D09 没有引用旧算法，控制面/最终引用
切断和物理退役继续交所属 D12/D13/D17/D18，生产清理由 C01 单独负责。
